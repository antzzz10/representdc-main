**1 BLOCKER, 7 MATERIAL findings. Do not publish this as a permanent archive yet.** Read-only review of staged files; nothing modified. An unstaged `ingest.mjs` edit appeared during review; findings below concern the index. Tracker conclusions concern the local checkout and generated public data, not a freshly verified deployment.

1. **BLOCKER — Raw history is not permanently preserved.** `scripts/ingest.mjs:37–42`, `.github/workflows/update.yml:58–67`, `README.md:37`. Daily runners discard ignored `raw/`; monthly runners skip writing unchanged XML before constructing the tarball. With no changes, `raw/` does not exist and publication fails; otherwise the “every measure” snapshot is incomplete. More fundamentally, versions observed and superseded between monthly runs disappear permanently. Preserve each distinct raw version durably when observed. The unstaged edit addresses monthly raw population, but not intermediate-version loss.

2. **MATERIAL — Checkpoint and parser updates are discarded when XML bytes match.** `scripts/ingest.mjs:29–37`. A changed sitemap timestamp with identical XML never updates the stored timestamp, causing daily refetches indefinitely. Similarly, `--force` cannot persist corrected normalization or a new parser version for unchanged XML. An upstream change retaining its lastmod is invisible until monthly force; SHA checking happens only after download. Persist checkpoint/parser changes independently of content changes.

3. **MATERIAL — Missing official records can produce a successful publication.** `scripts/ingest.mjs:33,54`, `.github/workflows/update.yml:43–55`. XML 404s populate `missing` but do not fail the run. New measures can remain absent, while existing missing upstream records retain stale facts without a per-record warning. Coverage reports missing files but does not gate publication. Define and enforce an explicit incomplete-data policy.

4. **MATERIAL — “Stage” is an undocumented coarse interpretation.** `scripts/export.mjs:20–24,58,79`, `README.md:36`. Every nonpassing measure, including committee-reported bills, exports as `introduced`. Independent chamber-passage flags also do not establish agreement on identical text; `passed-both` can precede resolving differences. Simple resolutions finish in one chamber; concurrent resolutions require both, without enactment. Export explicit chamber milestones and a separate measure-type-aware disposition, documenting the derivation rather than presenting it as an official status.

5. **MATERIAL — Preservation scope falls short of the earlier design.** `scripts/lib.mjs:68–75,119–121`, `.github/workflows/update.yml:64`. Text versions remain external links; no bill-text content is archived. Votes retain references without collecting available tallies/member choices. The earlier review explicitly required these. Link loss would leave the purported permanent archive unable to reconstruct those materials. Either implement preservation or clearly narrow the archive’s stated scope.

6. **MATERIAL — H.R. 5525 is wrongly classified and counted.** Tracker `src/data/bills.json:1640`, `scripts/generate-stats.js:42–60`. Archive `bills/119/hr/5525.json:97–118` records only March 18 committee markup and an order to report, **not House passage**. Correcting this entry alone changes generated passed/pending counts **15→14 / 82→83**, leaving total 97 unchanged. `check-published-claims.js:129` derives its expected count from the same erroneous stages; I ran it and it passed while announcing 15 chamber-cleared measures. It validates internal agreement, not official support.

7. **MATERIAL — Observation dates become legislative-event dates.** Tracker `scripts/monitor-bills.js:577` stamps stage changes with today despite already fetching the official latest-action date at `:385`. `RecentActivity.jsx:37–40,84` uses it for recency and displayed dates; `PageSummary.jsx:39–40` displays it as movement. Delayed detection/backfills therefore manufacture recent activity and reorder events. Store observation time separately and use the relevant official action date.

8. **MATERIAL — Coverage conflates rider provisions with parent bills.** `scripts/export.mjs:98–105`, `reports/coverage.json:45–50`. It compares each entry’s status to its first measure’s status. An enacted parent does not prove a proposed rider survived. The H.R. 7148 rider mismatch therefore cannot establish a tracker error. Report parent status separately and require provision-level evidence.

Workflow permissions/concurrency and UTC cron selection are reasonable; same-day release retries collide on the existing tag (`update.yml:63–65`). README claims that websites already consume this archive are premature.

**New findings**

- **BLOCKER — deleting both files silently re-enables seeding.** [publish.mjs:107](scripts/news/publish.mjs:107) detects deletion only from the marker in `news.json`. If a mistaken deploy or edit deletes *both* news files before a run starts, `readFeed` and `readArchive` both return null; the run loads the seed ([fetch-news.mjs:137](scripts/fetch-news.mjs:137)). Its first-read baseline is then also the seed, so the only-grows checks cannot see later confirmations. The next publish replaces the permanent record with seed-based memory. **Fix:** establish initialization from evidence independent of both current files—for example, inspect branch history or maintain a separately protected durable sentinel—and refuse to bootstrap when prior initialization is established. Add a test deleting both files before the initial read.

- **BLOCKER — a valid but smaller archive can become the new permanent baseline.** The marker records the confirmed-item count ([archive.mjs:187](scripts/news/archive.mjs:187)), but `readArchiveOrRefuse` uses it only when the archive is absent ([publish.mjs:107](scripts/news/publish.mjs:107)). If the archive is replaced with a valid smaller one *before* the run’s first read, both copies checked by `assertArchiveOnlyGrows` already lack the lost items; the run accepts and republishes the smaller archive. **Fix:** at minimum reject an archive whose item count is below the marker’s recorded count; for detection of same-size substitutions, retain and verify stronger independent evidence, such as a digest or history. Test corruption before the first read, not only between read and push.

- **MATERIAL — an absent or malformed marker is interpreted as permission to seed, and a marker can be introduced without an archive.** `archiveWasInitialized` accepts the truthiness of `initialized` ([archive.mjs:191](scripts/news/archive.mjs:191)); `false`, a missing field, or a lost marker followed by archive deletion permits reseeding. Conversely, when the current feed has no `archive` field, a non-archive caller’s returned marker is left intact ([publish.mjs:199](scripts/news/publish.mjs:199)): a caller can write `{ initialized: true }` without writing an archive, making subsequent runs fail until repaired. The current Withhold implementation spreads the existing feed rather than inventing that marker, but the publishing boundary does not enforce this property. **Fix:** validate marker shape, reject ambiguous marker states, and ensure non-archive writers cannot introduce a marker. Use independent initialization evidence for a missing marker.

For the other requested paths: the current Withhold code preserves an existing marker, and the deploy code excludes both files and refuses a build containing either; the deploy tests check byte-for-byte preservation ([deploy.mjs:42](scripts/deploy.mjs:42), [deploy.test.mjs:96](scripts/eval/deploy.test.mjs:96)). I found no weakening of the judge-pass boundary, withholding precedence, or `verifyLive` in the reviewed paths ([publish.mjs:179](scripts/news/publish.mjs:179), [archive.mjs:373](scripts/news/archive.mjs:373), [publish.mjs:234](scripts/news/publish.mjs:234)).

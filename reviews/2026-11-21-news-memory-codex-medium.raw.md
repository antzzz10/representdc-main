**Recommendation: do not ship yet.** I found two BLOCKER and three MATERIAL defects affecting the archive, publication invariant, and feed alerts.

- **BLOCKER — A missing archive is treated as a first run even after the archive has existed.** [scripts/news/publish.mjs:88](scripts/news/publish.mjs:88), [scripts/fetch-news.mjs:360](scripts/fetch-news.mjs:360). If an earlier deploy or another writer deletes `api/news-archive.json`, the next scan silently substitutes the seed and writes it as the new archive. The growth check receives `null`, so every confirmation accumulated since the seed is lost from the permanent record. This also applies if the file disappears between the initial read and a push retry. **Fix:** distinguish a verified first initialization from unexpected deletion using durable branch state or history; fail closed on subsequent absence. Test deletion both before a run and between attempts.

- **BLOCKER — A changed headline can be published beside a summary judged against different text.** [scripts/fetch-news.mjs:363](scripts/fetch-news.mjs:363). The retry comparison checks only ordered links. For example, while a run is generating a summary from a pending article’s current headline, another writer can confirm the same link using its older stored headline. Reapplying the run then displays that older headline, but the links match, so the summary and judge pass remain attached to different article text. **Fix:** compare the full ordered article payload supplied to the summarizer and judge—at least link, title, source, and date—and withhold on any difference. Add a concurrent confirmation test with the same link and different title.

- **MATERIAL — The seed permanently confirms clearly unrelated material.** [scripts/news/seed-archive.json:75](scripts/news/seed-archive.json:75), [scripts/news/seed-archive.json:131](scripts/news/seed-archive.json:131). “The 51st’s first crossword puzzle” and “The 51st in print!” are seeded as confirmed and will never be re-judged, although their titles do not establish relevance to statehood or home rule. Two historical publications reproduce two filter errors; they do not establish editorial correctness. **Fix:** audit the seed against the relevance standard, remove unsupported entries before initialization, and retain evidence for the selected records.

- **MATERIAL — Failure tracking stops whenever a run cannot publish.** [scripts/fetch-news.mjs:126](scripts/fetch-news.mjs:126), [scripts/fetch-news.mjs:160](scripts/fetch-news.mjs:160). Health is persisted only with a successful feed publication. If one feed fails continuously while the filter, archive read, or push also fails, `failingSince` never advances on the branch; after recovery it starts again, potentially delaying or preventing the promised two-day alert. An all-feed failure returns before health is checked at all. **Fix:** persist feed-health observations independently and safely, including failed publication paths, or explicitly redesign the alert around durable run observations. Test consecutive failures interspersed with filter and push failures.

- **MATERIAL — An issue can be closed while a feed is still failing.** [.github/scripts/news-feed-alert.sh:47](.github/scripts/news-feed-alert.sh:47). `FEED_ALERT` contains only sources failing for at least two days. If the previously alerted source recovers while another source has failed for one day, the list becomes empty and the script comments that every source recovered and closes the issue. **Fix:** pass both the thresholded list and whether any source currently fails; close only when all are healthy, and update the issue accurately during the transition.

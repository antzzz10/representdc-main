# Statehood Stakeholder Map (working doc)

**Status: draft, partially verified, not live anywhere.** This is a running
content/planning doc for the "meet the movement" stakeholder map — it exists to
iterate on quickly, not to ship as-is. Verification status is marked per org below;
unverified entries are seeded from the Action & Persona IA Brainstorm doc
(`reference/brand/RepresentDC Action & Persona IA Brainstorm.dc.html`) plus general
knowledge and still need a real fact-check against the org's own site before shipping,
per `DEVELOPMENT-GUIDELINES.md`.

**Correction (2026-07-26):** an earlier draft of this doc wrongly conflated the
external "Statehood Pledge" org with RepresentDC's own candidate-accountability tool.
They are not the same thing — see the naming note below.

## Naming: two different things called "statehood pledge"

- **Statehood Pledge** (`dcstatehoodpledge.org`) is a real, external, volunteer-run
  project — **national in scope**, tracking pledge signers among candidates and
  elected officials across multiple states (U.S. Senate, state lieutenant governor,
  state senate, etc.), not just D.C. It's one of three tools run by the same single
  independent volunteer, with no formal org name — see the combined Tier 1 entry
  below.
- **RepresentDC's own tool** (`candidates.representdc.org`, the repo internally named
  `dc-statehood-pledge`) should be referred to as the **Statehood Candidate
  Questionnaire** — D.C.-focused (2026 candidates specifically), and must not be
  confused with or presented as the same thing as the external Statehood Pledge above.
  The repo's internal codename predates this distinction being drawn clearly; worth a
  separate check on whether that site's own UI needs a wording fix too (not done in
  this pass — out of scope for this repo).

## End vision

Two connected things, per the original brainstorm and confirmed 2026-07-26:

1. **A visual map** of the main orgs doing D.C. statehood work and how they relate to
   each other — not a flat logo wall, since it's a real layered coalition, and
   rendering that as one undifferentiated list would misrepresent the structure.
2. **A matching tool**: "if you want *this*, here's who to connect with" — lets a
   visitor go from their own goal (research, local organizing, party politics, student
   involvement, funding, holding candidates accountable) straight to the org that's
   actually the right fit.

The categorization below is built to serve both at once — grouped by what an org
actually *is* (for the visual map), each tagged with a plain-language "best for" line
(for the matching tool).

## Tier 2 — the wider coalition

Together for DC's own steering committee already lists 16+ organizations (Center for
Economic Democracy, DC Appleseed, DC Fiscal Policy Institute, DC Jobs With Justice, DC
Justice Lab, DC Chapter NOW, Fair Budget Coalition, Miriam's Kitchen, National LGBTQ
Task Force, Public Citizen, SPACEs in Action, Taskforce for Democracy, DCNOW, and
others, alongside several Tier 1 orgs above), and reproducing that full list here would
drift out of date fast. Instead: a single line — "and a growing coalition of 100+
organizations" — crediting and linking directly to Together for DC's own coalition
page (`togetherfordc.org`) as the living source of truth, dated to whenever we last
checked it.

## Open questions for the next iteration

  attempted here. For the tools node specifically: how do three sub-tools read as one
  map entry without looking like a single flat link?
- **Matching-tool UX** — how a visitor expresses "what they want" and how that maps to
  the "best for" column above.
- **Statehood Candidate Questionnaire's visual treatment** — needs to read as "our own
  tool," not a tenth peer entry, on whatever the final map layout turns out to be.
